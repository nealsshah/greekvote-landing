# Agent Context

## Design Context

Before changing any UI, read [`PRODUCT.md`](./PRODUCT.md). It defines the strategic context for this landing page and is the source of truth for register, audience, voice, anti-references, and design principles.

### TL;DR

- **Register**: brand (marketing landing page — design is the product).
- **Primary user**: recruitment chairs deciding in under a minute, on a phone, whether to push GreekVote to their e-board.
- **Job to be done**: convert to a free first recruitment cycle, self-serve.
- **Voice**: peer-level (someone who's run rush before), not vendor-level. Confident, fair, modern. No hype, no manufactured urgency.
- **Visual references**: Notion / Linear / Arc — playful-but-credible product marketing for prosumer tools.
- **Anti-references**: generic blue SaaS (Salesforce, HubSpot, ChapterBuilder, OmegaFi); frat-bro aesthetic (Greek letters, party photos, navy + gold); AI-slop scaffolding (numbered eyebrows on every section, uppercase tracked kicker on every heading, italic-serif accent on every H2).
- **Accessibility**: WCAG 2.1 AA, mobile-first scrutiny. Body contrast ≥ 4.5:1, tap targets ≥ 44×44px, respect `prefers-reduced-motion`, semantic HTML.

### Design Principles

1. Fair by design, on every surface — no manufactured urgency, no "limited spots" theater.
2. Speak as a teammate, not a vendor — every line answers "would a recruitment chair say it this way?"
3. Mobile is the canonical surface — phone first, desktop is the variant.
4. One specific claim beats five vague benefits.
5. Vary the cadence — sections should not all look like the same template.
